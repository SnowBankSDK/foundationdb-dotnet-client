# FDB0800: API removed at API version 800

| | |
|---|---|
| Source | `[Obsolete]` attributes in FoundationDB.Client |
| Severity | Warning |
| Code fix | No |

## Message

'{0}' is obsolete: 'Tenants were removed from FoundationDB at API version 800, and only work with API versions below 800. Store each tenant under its own directory subspace instead (Directory Layer, one FdbPath per tenant).'

`{0}` is the tenant type or member. `FdbDatabaseOption.UseConfigDatabase` reports the configuration database instead of tenants.

## Why

FoundationDB 8.0 removed tenants and the configuration database (see the [8.0 release notes](https://github.com/apple/foundationdb/blob/8.0.0/documentation/sphinx/source/release-notes/release-notes-800.rst)). These APIs remain in the binding for API versions below 800, so an application on a 7.x cluster still compiles and runs. At API version 800 and later, every tenant method throws `NotSupportedException`. The check happens before any call to the native client: with `fdb_c` 8.0, the process aborts on a call to a tenant function.

The warning appears on the tenant types and on every member that returns a tenant:

| Kind | APIs |
|---|---|
| Types | `IFdbTenant`, `FdbTenant`, `FdbTenantName`, `FdbTenantMetadata`, `FdbTenantMode`, `FdbTenantSubspace`, `FdbTenantExtensions`, `Fdb.Tenants`, `IFdbTenantHandler` |
| Members | `IFdbDatabase.GetTenant` and its extension overloads, the `Tenant` property of `IFdbReadOnlyTransaction` and `FdbOperationContext`, `IFdbDatabaseHandler.OpenTenant` |
| Options | `FdbDatabaseOption.UseConfigDatabase` |

## Bad

```csharp
var tenant = db.GetTenant(FdbTenantName.Create(Slice.FromStringAscii("acme")));
await tenant.WriteAsync(tr => tr.Set(Slice.FromStringAscii("greeting"), FdbValue.ToTextUtf8("Hello")), ct);
```

## Good

```csharp
var location = db.Root["Tenants"]["acme"];
await db.WriteAsync(async tr =>
{
	var subspace = await location.CreateOrOpenAsync(tr);
	tr.Set(subspace.Key("greeting"), FdbValue.ToTextUtf8("Hello"));
}, ct);
```

## Suppress

To use tenants on a 7.x cluster, suppress the warning in the project file:

```xml
<NoWarn>$(NoWarn);FDB0800</NoWarn>
```

The `[Obsolete]` attributes of the `netstandard2.0` build have no diagnostic id, so the warning in a .NET Framework project is `CS0618`: suppress that id there.
