Released on 2026-10-XX.

In this release: the `SnowBank.Core` and `FoundationDB.Client` packages run Roslyn analyzers in the build of
the projects that reference them, `SnowBank.Core` turns off the reflection path in a trimmed or Native AoT
publish, the native client loads from fixed paths, and the Aspire integration opens `fdbcli` and FdbShell from
the dashboard.

# Analyzers

## The packages run Roslyn analyzers in your build

After the upgrade, a project that references `SnowBank.Core` or `FoundationDB.Client` reports diagnostics with
`SBK` and `FDB` ids. Each one points at code that fails at run time, can corrupt or lose data, or does more
work than it needs to.

Both packages now carry Roslyn analyzers and their code fixes. A project that references `FoundationDB.Client`
runs both sets; a project that references only `SnowBank.Core` runs the `SBK` rules. A compiler older than
Roslyn 4.8 (the .NET 8 SDK) skips them.

| Tier | Severity | IDs |
|---|---|---|
| Fails every time at run time, or does not compile | Error | `SBK0xxx`, `FDB0xxx` |
| Can corrupt or lose data | Warning | `SBK1xxx`, `FDB1xxx` |
| Correct but slower | Warning | `SBK2xxx`, `FDB2xxx` |

| [FDB0100](../analyzers/FDB0100.md) | Removed API | Error |

An error-tier rule reports code that already throws every time it runs, or that sits next to a compile error
for a removed API, so it does not stop a build that worked. A warning-tier rule stops the build of a project
that sets `TreatWarningsAsErrors`. The performance rules (`SBK2xxx`, `FDB2xxx`) do not run in a test project,
recognized by a reference to NUnit, xUnit, MSTest or TUnit: a test uses the plain factories on purpose, and the
BCL encoders as oracles.

```csharp
public static bool HasDiscount(JsonObject order)
	=> order["discount"] == null;
// warning SBK1003: A JsonValue is never a null reference: a missing member reads as JsonNull.Missing. Test it with IsNullOrMissing().

public static bool HasDiscountFixed(JsonObject order)
	=> order["discount"].IsNullOrMissing();
```

Each rule has a page with its rationale, examples and code fix: see the [analyzer index](../analyzers/index.md).
What to do: fix the code the rule reports, or change the severity of one rule or of a whole tier in
`.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SBK1004.severity = suggestion
dotnet_analyzer_diagnostic.category-FdbPerformance.severity = none
```

# SnowBank

## The reflection path is off in a trimmed or Native AoT publish

If an application publishes trimmed or Native AoT and serializes a type that has no generated converter,
CrystalJson now throws `JsonReflectionDisabledException` where 7.4.6 ran the reflection path. In 7.4.6 the
reflection switches were on by default, and their guards also silenced the trim warnings, so a trimmed
application ran reflection over members that the trimmer may have removed, with no warning at publish.

In 7.4.7 the `SnowBank.Core` package sets two switches to `false` when the project sets `PublishTrimmed` or
`PublishAot`: `SnowBank.Data.Json.CrystalJson.IsReflectionSupported` (the CrystalJson reflection path) and
`SnowBank.Data.Tuples.TuPack.IsReflectionSupported` (the reflection-based tuple encoders of exotic element
types). The trimmer then removes the reflection code. A switch that the application already sets with its own
`RuntimeHostConfigurationOption` keeps the application's value. A build without `PublishTrimmed` or `PublishAot`
is not affected.

Who is affected: a trimmed or Native AoT application that serializes a type with no generated converter, or
packs a tuple element of an exotic type (a nullable of a type that is not well-known, a `ValueTuple`, a boxed
`object`). What to do: register the type with `[CrystalSerializable(typeof(T))]` in a generated container. If
the application must keep the reflection path, opt in, and keep the reflected members with the trimmer
annotations yourself:

```xml
<PropertyGroup>
	<CrystalJsonIsReflectionSupported>true</CrystalJsonIsReflectionSupported>
	<TuPackIsReflectionSupported>true</TuPackIsReflectionSupported>
</PropertyGroup>
```

## `SnowBank.Core` builds without trim and AoT warnings

A trimmed publish against 7.4.6 reported trim warnings from the code of `SnowBank.Core` itself
(`CrystalJsonCodec<T>.EncodeValue`, `CrystalJsonDomWriter`, `CrystalJsonTypeResolver`, and others). In 7.4.7
the trim and AoT analysis of the library reports none:

- The `ToJsonBytes` and `ToJsonSlice` extension methods of `JsonValue` and `IJsonSerializable` call the
  `JsonSerialize` method of the value instead of the reflection path. New `CrystalJson.ToJsonSlice` overloads do the same for
  an `IJsonSerializable` value.
- The enum literal cache reads the underlying values of an enum type, which Native AoT supports, on .NET 8
  and later.
- A decoded embedded tuple is packed again from its bytes, see [the tuple fix](#fixed-a-decoded-embedded-tuple-packs-again-with-its-original-bytes).

Two members now declare the reflection they use, so a trimmed or Native AoT build reports `IL2026` and
`IL3050` at the call site instead of hiding them: `CrystalJson.Dump`, and the `CrystalJsonCodec<T>`
constructors and `CrystalJsonCodec.GetEncoder<T>(settings, resolver)` overload that take no converter. To
remove the warning from a codec, pass a generated converter, as in the next section.

## `CrystalJsonCodec` uses the converter it is given

If you created a `CrystalJsonCodec<T>` with a generated converter, it did not use it, or it could not decode:

- `CrystalJsonCodec.GetEncoder(converter, ...)` returned a codec without the converter. It serialized through
  the reflection path, which a trimmed application cannot rely on.
- `new CrystalJsonCodec<T>(converter, ...)` threw `JsonBindingException` ("Cannot parse JSON String as an
  Object.") in `DecodeValue`: it passed the encoded bytes to the converter as a JSON string instead of parsing
  them. The constructor also ignored its `resolver` argument.

In 7.4.7 both forms encode and decode with the converter, and use the resolver they receive.

```csharp
public sealed record Order(string Id, decimal Total);

[CrystalJsonConverter]
[CrystalSerializable(typeof(Order))]
public static partial class AcmeSerializers { }

var codec = CrystalJsonCodec.GetEncoder(AcmeSerializers.Order.Default);
Slice bytes = codec.EncodeValue(new Order("ORD-42", 129.90m));
// => {"Id":"ORD-42","Total":129.90}
Order? order = codec.DecodeValue(bytes);
// => Order { Id = ORD-42, Total = 129.90 }
```

## Fixed: a decoded embedded tuple packs again with its original bytes

`TuPack.Pack` wrote different bytes for a tuple that contains a decoded embedded tuple (a `SlicedTuple`, what
`TuPack.DecodeKey<..., IVarTuple, ...>` returns for an embedded tuple). The embedded items kept their top-level
encoding, and a null item uses another encoding inside an embedded tuple. In 7.4.7 the bytes are the original
ones, through `TuPack.Pack` and through `TuPack.EncodeKey`, without the reflection path.

```csharp
var inner = STuple.Create("a", default(string), 123L);
Slice packed = TuPack.Pack(STuple.Create<object?, object?, object?>("x", inner, 456L));

var (x, decoded, n) = TuPack.DecodeKey<string, IVarTuple, long>(packed);
TuPack.Pack(STuple.Create<object?, object?, object?>(x, decoded, n)) == packed;
// => true (7.4.6: false)
```

## The testing packages support NUnit 5 consumers and order tests with `[Canary]` and `[RunOrder]`

A test project that moved to NUnit 5 and used the `Throws.InstanceOf<T>(out var captured)` helper of
`SnowBank.Testing.Common` failed with `MissingMethodException`, because NUnit 5 changed the return type of the
NUnit method that the helper called. In 7.4.7 the helper works on NUnit 4 and NUnit 5. The packages still
require NUnit 4.6.1 or later.

NUnit 5 marks `[Order]` as obsolete. Two new attributes of `SnowBank.Testing` order the tests of a fixture the
same way on NUnit 4 and NUnit 5. `[Canary]` runs a test first: an assumption whose failure explains the
failures that follow. `[RunOrder(n)]` runs the basic tests before the advanced ones. Neither makes a test depend
on another, so every test still runs and reports its own result, and the order only holds for tests that do
not run in parallel.

```csharp
[TestFixture]
public class OrderStoreFacts
{
	[Test, Canary]
	public void Test_Hash_Algorithm_Did_Not_Change() { /*...*/ }

	[Test, RunOrder(10)]
	public void Test_Can_Read_And_Write() { /*...*/ }

	[Test, RunOrder(20)]
	public void Test_Can_Read_Your_Writes() { /*...*/ }
}
```

`SnowBank.Testing.Framework.Playwright` requires `Microsoft.Playwright` 1.63.0, which fixes a close event
without a code or a reason. Install the browsers of that version (`playwright install`) on the test hosts.

## Other changes in `SnowBank.Core`

- The JSON writer searches for the characters to escape with `SearchValues` on .NET 8 and later.
- Base62 decoding reads the input through a bounds-checked span.
- The obsolete `==` and `!=` operators of `Slice?` name `IsNull` in their message, instead of `IsNil`, which
  does not exist.
- The obsolete two-member `JsonObject.ReadOnly.Create` names `JsonObject.ReadOnly.Create([ (k, v), ... ])` in
  its message, instead of `JsonObject.Create`, which builds a mutable object.

# FoundationDB

## The native client loads from fixed paths

If the native client of a host is only found through `PATH` (Windows) or `LD_LIBRARY_PATH` (Linux), the
binding now throws `DllNotFoundException` when it opens the database, with the paths it checked. In 7.4.6 the
runtime and the operating system searched for the library, and that search visits folders that other users or
programs may be able to write to: a library planted there ran inside the process.

In 7.4.7 the binding checks fixed paths, in this order: `runtimes/{rid}/native/` under the application folder
and the application folder (where the `FoundationDB.Client.Native` package deploys the library), then the
location of the official client installer.

| Platform | File | Location of the official client |
|---|---|---|
| Windows | `fdb_c.dll` | `%ProgramFiles%\foundationdb\bin\fdb_c.dll` |
| Linux | `libfdb_c.so` | `/usr/lib/libfdb_c.so` |
| macOS | `libfdb_c.dylib` | `/usr/local/lib/libfdb_c.dylib` |

Who is affected: a host whose native client is in another folder. What to do: add the
`FoundationDB.Client.Native` package with the major.minor of the cluster (`7.4.*` for a 7.4 cluster), or set
the path of the library. `UseSystemNativeClient()` restores the search of the operating system, with its risk:

```csharp
services.AddFoundationDb(740, options => options.NativeLibraryPath = "/opt/foundationdb/lib/libfdb_c.so");

services.AddFoundationDb(740, options => options.UseSystemNativeClient());
```

Without dependency injection, `Fdb.Options.SetNativeLibPath(path)` sets the path.

## `AddFoundationDb` sets network options

To set a network option, for example to load the other versions of the native client of the multi-version
client, an application had to call `Fdb.Options` before the provider started. In 7.4.7
`FdbDatabaseProviderOptions.SetNetworkOption` sets it where the provider is registered, and the Aspire
`configureProvider` callback can call it too. The provider applies the options in the order of the calls,
after the trace and TLS options. The network thread starts once per process, so the options of the first
provider that starts apply to the whole process.

```csharp
services.AddFoundationDb(740, options => options
	.SetNetworkOption(FdbNetworkOption.ExternalClientDirectory, "/opt/foundationdb/clients")
);
```

## `AddFakeDb` opens the cluster root when no root is given

`services.AddFakeDb(730)`, the registration the emulator README shows, failed at the first transaction with
`ArgumentException` ("Directory Subspace path must absolute."): the omitted `root` argument was an empty
relative path, not the cluster root. In 7.4.7 it opens the cluster root, `FdbPath.Root`. `FakeDbProvider.IsAvailable`
was `false` for the whole life of the provider; it is now `true` once the database is open.

```csharp
var services = new ServiceCollection();
services.AddFakeDb(730);
await using var sp = services.BuildServiceProvider();
var provider = sp.GetRequiredService<IFdbDatabaseProvider>();

await provider.WriteAsync(async tr =>
{
	var subspace = await provider.Root["Acme"].ResolveOrCreate(tr);
	tr.Set(subspace.Key("hello"), FdbValue.ToTextUtf8("world"));
}, ct);
// 7.4.6: ArgumentException, Directory Subspace path must absolute.
```

## Aspire: `fdbcli` and FdbShell in the dashboard, and a data volume per AppHost

Three methods add commands to the terminal dock of the Aspire dashboard:

- `WithFdbCli()` opens `fdbcli` inside the cluster container.
- `WithFdbShell()` runs the FdbShell tool of the same version as the hosting package, with
  `dotnet tool exec`, and the native client of the `FoundationDB.Client.Native` package of the AppHost. The
  AppHost throws at startup when that package is missing or of another FoundationDB branch.
- `WithFdbShell<TProject>()` runs FdbShell from a project of the solution.

The cluster data volume was `fdb_data` for every AppHost, so the clusters of two AppHosts, two worktrees or two
FoundationDB versions shared their data files, and a 7.4 server upgrades the data files of a 7.3 cluster in
place. `WithDataVolume(name, isReadOnly)` gives the cluster a volume of its own. Without a name, the name is
generated from the AppHost and the resource, so each copy of the AppHost gets its own volume.

```csharp
builder.AddFoundationDb("fdb", apiVersion: 740, root: "/Acme")
	.WithDataVolume()
	.WithFdbCli()
	.WithFdbShell();
```

Two fixes in the client integration (`FoundationDB.Aspire`):

- `ReadOnly` in the connection string had no effect: the client looked it up under a misspelled key.
  `ReadOnly=true` now opens a read-only database.
- The AppHost wrote the content of the cluster file in the native library entry of the connection string, and
  the client did not read the native preloading entry that the AppHost writes. Both now match.

## FdbShell and FdbTop connect to an Aspire resource

`fdbshell --aspire` assumed a cluster on `127.0.0.1:4550`. In 7.4.7, `--aspire [name]` reads the connection
string that Aspire injects for the resource (`ConnectionStrings__<name>`), and fails with the names it found
when it is missing. FdbShell starts in the root folder, loads the native library of the connection string, and
stops when the branch of its native client differs from the version of the cluster. FdbTop accepts the same
option.

When the cluster file is missing, unreadable or invalid, FdbShell stops with a hint instead of retrying with no
delay; other connection failures retry with a delay from 100 ms to 2 s. The `--spawn`, `--child` and `--parent`
options are removed.

## The test server fails fast when Docker is not running

A suite built on `FoundationDB.Testing` failed with `NullReferenceException`, or waited without end for a cluster,
when the Docker daemon was not running. In 7.4.7 `FdbServerTestContainer` throws `InvalidOperationException`
("Could not reach a Docker daemon. Check that Docker is running, ..."), a test fails when the server did not
start, and the database of a test has a 15 second default timeout, as in `OpenTestDatabaseAsync`.

# Breaking changes

- **The packages run Roslyn analyzers in your build.** A project that sets `TreatWarningsAsErrors` fails on a
  warning-tier finding. Fix the code, or change the severity in `.editorconfig`
  (`dotnet_diagnostic.<ID>.severity`, or `dotnet_analyzer_diagnostic.category-<Category>.severity`).
- **The reflection path is off in a trimmed or Native AoT publish.** A trimmed application that serializes a
  type with no generated converter throws `JsonReflectionDisabledException`. Register the type in a generated
  container, or opt in with `CrystalJsonIsReflectionSupported=true` (and `TuPackIsReflectionSupported=true` for
  the tuple encoders).
- **The native client loads from fixed paths.** A host whose native client is only found through `PATH` or
  `LD_LIBRARY_PATH` throws `DllNotFoundException`. Add `FoundationDB.Client.Native`, set
  `FdbDatabaseProviderOptions.NativeLibraryPath`, or call `UseSystemNativeClient()`.
- **`CrystalJson.Dump` and the `CrystalJsonCodec<T>` constructors without a converter declare their
  reflection.** A trimmed or Native AoT build reports `IL2026` and `IL3050` at their call sites. Pass a
  generated converter to the codec.
- **FdbShell removed the `--spawn`, `--child` and `--parent` options.** A script that passes them fails to start
  the shell.
- **`SnowBank.Testing.Framework.Playwright` requires `Microsoft.Playwright` 1.63.0.** Install the browsers of
  that version on the test hosts.
- **The net11.0 build targets .NET 11 RC2.** A consumer that builds the net11.0 target on the RC1 SDK fails to
  restore the `11.0.0-rc.2` packages; install the .NET 11 RC2 SDK.
- Everything else in this release is additive.
